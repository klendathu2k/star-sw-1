# pams/geometry — STAR Detector Geometry Modules

## Overview

`pams/geometry/` defines the **STAR detector geometry** in the AGE macro language
(`.g` files).  Each `.g` file is preprocessed by the `agetof` tool into FORTRAN,
which is then compiled and linked with STARSIM/GEANT3.  The resulting code
describes every detector's shapes, materials, media, sensitive volumes, and hit
definitions used by the Monte-Carlo simulation.

The directory contains:

- **`geometry/geometry.g`** — the master steering module; selects sub-modules
  and their versions based on a geometry tag string (e.g. `y2014a`).
- **35+ sub-module directories** — one per detector or support structure, each
  containing one or more versioned `.g` files.
- **`idl/`** — C-language interface definitions auto-generated by AGI; consumed
  by reconstruction code.
- **`release.note`** — CVS change history for the master geometry.

## How `geometry.g` works

`geometry.g` declares a single AGE **module** named `geometry` (author: Pavel
Nevski, created August 1998, ~3 000 lines, ~300 CVS revisions).  It is the
sole entry point called by STARSIM when a `DETP GEOM <tag>` command is issued.

```
DETP GEOM y2014a        ← issued in a STARSIM kumac or command file
```

The steering logic works as follows:

1. **DETP bank read** — the tag string is read from the `GEOM` DETP bank via
   `ASLGETBA`.  If the bank is empty the module exits immediately (geometry was
   already built externally, e.g. by AGML).

2. **Default flags** — all detector on/off switches (`CAVE`, `PIPE`, `SVTT`,
   `TPCE`, …) and integer version codes (`SvttConfig`, `BtofConfig`, …) are set
   to canonical defaults.

3. **Tag case statement** — the tag string is matched against a long chain of
   `Case` blocks.  Each block sets the on/off switches and version integers that
   define that detector configuration.  Macro-style `replace … with …` aliases
   (`exe BTOFc6`, `exe TPCE04`, …) expand into groups of flag assignments.

4. **Sub-module instantiation** — after the tag is parsed, each detector that
   is switched on is created via `AgSModule` (or a direct FORTRAN call for
   legacy modules).  The appropriate versioned file (`tpcegeo3.g`,
   `calbgeo2.g`, …) is selected by the version integer.

5. **GDAT bank** — the tag string and magnetic-field scale factor are stored in
   a `GDAT` Zebra bank in the FZD output for later reconstruction use.

### Version integers

Every detector has one or more `<Name>Config` integers (e.g. `TpceConfig`,
`SvttConfig`, `BtofConfig`).  A value of `0` means the subsystem is absent; a
positive value selects the specific source file and parameter set:

| Config value | File selected |
|---|---|
| `TpceConfig = 1` | `tpcegeo.g` |
| `TpceConfig = 2` | `tpcegeo1.g` |
| `TpceConfig = 3` | `tpcegeo2.g` |
| `TpceConfig = 4` | `tpcegeo3.g` |
| `TpceConfig = 31` | `tpcegeo3.g` (subversion 1) |

## AGE `.g` file structure

Each sub-module `.g` file follows a standard AGE template:

| Block | Purpose |
|---|---|
| `Module <NAME> is …` | Module declaration; sets the top-level AGE namespace |
| `Author / Created` | Metadata comments |
| `Structure <SNAME> { … }` | Declares a named parameter structure (maps to a ZEBRA bank) |
| `Fill <SNAME>` … `EndFill` | Provides default numeric values for a structure |
| `Content <V1>,<V2>,…` | Lists all GEANT volume names defined in this module |
| `Create <VNAME>` | Instantiates a GEANT volume |
| `Position <VNAME> in <MOTHER>` | Places a volume inside a mother volume |
| `Hits <VNAME> …` | Declares sensitive-volume hit variables |
| `GSTPAR` calls | Sets per-medium tracking thresholds |
| `AgSFlag` calls | Sets AGS simulation flags (e.g. secondary-track association) |

Volumes are defined as GEANT3 shapes (BOX, TUBE, TUBS, PGON, …) with material
and medium properties looked up from the AGE material database.  Sensitive
volumes produce hits that are later digitised by the detector response
simulation.

## IDL files

The `idl/` sub-directory contains three C-language interface files
auto-generated by the AGI tool from the corresponding `Structure` declarations
in the `.g` files.  They are consumed by the STAR reconstruction framework to
read geometry parameters from Zebra banks.

| File | Structure | Description |
|---|---|---|
| `calb_calg.idl` | `calb_calg` | BEMC barrel calorimeter geometry parameters: inner radius, η cut, crack width, scintillator layer thicknesses, etc. |
| `calb_calr.idl` | `calb_calr` | BEMC barrel calorimeter row (tower) parameters |
| `mfld_mflg.idl` | `mfld_mflg` | Magnetic field map parameters: field value, inner/outer field-volume radii and half-lengths |

These files are **auto-generated**; do not edit them by hand.

## Dependencies

### Build-time
- **`agetof`** — AGE-to-FORTRAN preprocessor; converts `.g` files to `.F`
  source before compilation.  Invoked by the STAR build system (`cons`/`scons`).
- **GEANT3 / STARSIM** headers — AGE common blocks (`AGECOM`, `GCUNIT`,
  `GCONST`, `GCBANK`, `GCPHYS`, `GCCUTS`, `GCFLAG`, etc.) must be visible at
  compile time.

### Run-time
- **STARSIM** calls the `geometry` module via `AgSModule('geometry')` after
  processing the `DETP GEOM <tag>` command.
- **GEANT3** volume and material databases (`JVOLUM`, `JMATE`, `JTMED`) must
  be initialised before module execution.
- **Zebra** is used internally for the `GDAT` parameter bank.

### Called by
- STARSIM kumac / steering scripts: `DETP GEOM <tag>`
- The STAR offline framework (`StMCAnalysisMaker` and similar) when running
  full Monte-Carlo simulations.
